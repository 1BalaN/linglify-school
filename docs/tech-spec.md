# Техническое задание на дипломный проект "Linglify MVP+"

---

## 1. Общие сведения

### 1.1. Наименование проекта
**Linglify: MVP+ платформа для онлайн-обучения иностранным языкам**

### 1.2. Краткое описание
Дипломный проект представляет собой расширенную минимальную версию платформы для системного онлайн-обучения иностранным языкам. Платформа охватывает полный цикл образовательного процесса: от определения уровня языка до получения сертификата об окончании курса.

### 1.3. Сроки реализации
- **Общий срок:** 3,5 месяца (14 недель)  
- **Дата начала:** 10.02.2026  
- **Дата завершения:** 15.05.2026

### 1.4. Команда проекта
- **Разработчик:** 1 человек (студент)  
- **Инструменты:** AI-инструменты (GitHub Copilot, ChatGPT, Cursor IDE и др.)

### 1.5. Цели проекта
#### Бизнес-цели
- Создание рабочего прототипа образовательной платформы
- Проверка гипотезы о востребованности курсовой модели обучения
- Демонстрация коммерческой применимости решения
- Подготовка основы для масштабирования

#### Пользовательские цели
- Определение уровня языка через автоматизированный тест
- Выбор курса по уровню и целям
- Структурированное обучение с отслеживанием прогресса
- Коммуникация с поддержкой в реальном времени
- Получение сертификата по окончании обучения

#### Академические цели
- Демонстрация навыков fullstack разработки
- Применение современных архитектурных подходов
- Интеграция внешних сервисов
- Реализация автоматизации процессов

### 1.6. Целевая аудитория
1. Ученики: взрослые от 18 лет с уровнем языка A1–C1
2. Преподаватели: авторы курсов и преподаватели
3. Администраторы: управляющие платформой

### 1.7. Технологический стек
#### Backend
- Язык: TypeScript
- Фреймворк: Express.js
- База данных: PostgreSQL
- Кэширование: Redis
- ORM: Prisma
- Аутентификация: JWT + OAuth 2.0
- Real-time: Socket.io
- Расписания: node-cron

#### Frontend
- Фреймворк: React
- Сборка: Vite
- State Management: Redux Toolkit + RTK Query
- HTTP: axios
- UI: ShadcnUI
- Стилизация: Tailwind CSS
- Маршрутизация: React Router
- Формы: React Hook Form + Zod
- Чарты: Recharts
- Видео: React Player

#### Инфраструктура
- Frontend хостинг: Vercel
- Backend хостинг: Railway
- База данных: Neon
- Кэш: Upstash Redis
- Домен: бесплатный поддомен или .tk/.ml
- Менеджер пакетов: yarn

#### Внешние интеграции
- Платежи: Stripe (Test Mode)
- SMS: Twilio (trial)
- Email: Gmail SMTP
- Соцсети: Google OAuth, GitHub OAuth
- Аналитика: Google Analytics

### 1.8. Приоритеты реализации
#### Must-have (обязательно)
- Аутентификация и роли
- Каталог курсов
- Прохождение курса
- Прогресс обучения
- Placement test (упрощённый)
- Сертификат

#### Should-have (желательно)
- Stripe (test mode)
- Email уведомления
- Чат поддержки
- Статистика курсов

#### Could-have (если останется время)
- FAQ-бот
- Расширенная аналитика
- Автоматические отчёты
- Продвинутые рекомендации

## 2. Функциональные требования

### 2.1. Роли пользователей
#### 2.1.1. Гость
- Просмотр главной страницы
- Прохождение placement test
- Просмотр каталога курсов
- Регистрация

#### 2.1.2. Ученик
- Полный цикл обучения
- Управление профилем
- Покупка курсов
- Отслеживание прогресса
- Чат
- Получение сертификатов

#### 2.1.3. Преподаватель
- Создание и редактирование курсов
- Наполнение курсов контентом
- Просмотр статистики
- Общение с учениками
- Проверка заданий (базово)

#### 2.1.4. Администратор
- Управление пользователями
- Модерация курсов
- Просмотр системной статистики
- Управление настройками платформы
- Техническая поддержка

### 2.2. Основные сценарии использования
#### Сценарий 1: Placement Test и регистрация
1. Гость заходит на главную страницу
2. Проходит placement test (20 вопросов, адаптивная сложность)
3. Получает уровень A1–C1
4. Видит рекомендации курсов
5. Регистрируется через email/соцсети
6. Подтверждает телефон через SMS
7. Получает доступ к ЛК

#### Сценарий 2: Покупка и прохождение курса
1. Просмотр каталога
2. Выбор курса
3. Просмотр демо-урока
4. Покупка через Stripe
5. Доступ к материалам
6. Прохождение уроков
7. Выполнение тестов
8. Отслеживание прогресса
9. Получение сертификата

#### Сценарий 3: Создание курса преподавателем
1. Создание курса
2. Заполнение информации
3. Добавление модулей и уроков
4. Загрузка материалов
5. Создание тестов
6. Отправка на модерацию
7. Продажа курса
8. Статистика

#### Сценарий 4: Поддержка через чат
1. Ученик пишет в поддержку
2. Автоответы
3. Подключение оператора
4. История чата
5. Отправка файлов
6. Уведомления

### 2.3. Детализация ключевых функций
#### 2.3.1. Placement Test
- 15–20 вопросов
- 15–25 минут
- Типы: Multiple choice, Fill in the blanks, Reading, Listening
- Адаптивная сложность
- Результат: CEFR уровень, анализ, рекомендации

#### 2.3.2. Система авторизации
- Email + пароль
- Google OAuth
- Email подтверждение
- SMS подтверждение
- JWT access/refresh
- Rate limiting
- OWASP Top-10 защита

#### 2.3.3. Каталог курсов
- Фильтрация: уровень, категория, цена, рейтинг
- Сортировка: популярность, новизна, цена
- Карточка курса: информация, программа, преподаватель, отзывы, демо, цена

#### 2.3.4. Учебный процесс
- Последовательное открытие уроков
- Форматы: текст, видео, файлы, интерактив
- Тесты после уроков
- Автопроверка
- Прогресс и графики

#### 2.3.5. Система чатов
- Поддержка и групповые чаты
- Текст, файлы (до 5MB)
- История, статус, уведомления
- FAQ бот и эскалация

#### 2.3.6. Уведомления
- Приветственные, учебные, транзакционные, системные
- Email, SMS, внутренние
- Триггеры: 24/1 час, дедлайны, неактивность, достижения

#### 2.3.7. Сертификация
- Условия: завершение курса и финальный тест
- PDF с QR-кодом, данными и подписью
- Автогенерация и email отправка

### 2.4. State Management Architecture
#### 2.4.1. Redux Toolkit структура
Slices:
- auth, user, courses, placementTest, chat, notifications, ui

#### 2.4.2. RTK Query
- Кэширование, инвалидация, polling, optimistic updates, TypeScript

#### 2.4.3. WebSocket
- Real-time обновления
- Redux middleware
- Reconnect логика
